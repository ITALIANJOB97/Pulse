PULSE 0.2.4 — GITHUB PUBBLICO -> ARUBA -> MINT
============================================
Questo percorso mantiene il servizio blog già presente sul Mint. Si configura
sul hosting, senza comandi sul PC del negozio. Nessun token GitHub necessario.
Richiede che ITALIANJOB97/Pulse sia pubblica e abbia una Release completa.

REQUISITI
PHP CLI 8.1+ con curl, sodium e mbstring; accesso HTTPS a api.github.com e
release-assets.githubusercontent.com; processi Cron; cartella privata fuori
dalla radice pubblica. Per pacchetti fino a 100 MB usare memory_limit >=256 MB.

CONFIGURAZIONE ARUBA UNA TANTUM
1. Estrai PULSE-Relay-Hosting-0.2.4.zip. Carica i file di privata/ in una
   cartella fuori dalla radice del sito (percorso reale da verificare nel tuo
   piano), ad esempio /home/ACCOUNT/pulse-relay/. Non usare /myfile/Pulse/.
2. Rinomina blog-relay-config.example.php in config.php. Imposta web_root
   al percorso assoluto della radice pubblica e public_dir allo stesso
   percorso seguito da /myfile/Pulse. Imposta config.php con permessi 600.
   Non inserire alcun token. Eventuali credenziali della vecchia configurazione
   privata vengono ignorate: puoi rimuoverle da quel file e revocarle.
3. Pannello Aruba > Hosting Linux/WordPress > Processi Cron > Aggiungi Cron.
   Seleziona PHP, non HTTP/HTTPS, e il percorso di blog-relay-cron.php.
   Se richiede un comando completo, usa l’interprete PHP indicato dal pannello
   seguito dal percorso dello script. Esempio solo se corrisponde al piano:
   /usr/bin/php /home/ACCOUNT/pulse-relay/blog-relay-cron.php
4. Pianifica ogni 15 minuti. Controlla ultima esecuzione e Dettagli log errore.
   Esito previsto: "PULSE X.Y.Z available via blog."
   Le pianificazioni Aruba sono in UTC; l’intervallo ogni 15 minuti resta valido
   indipendentemente dal passaggio tra ora legale e solare.
5. Escludi stable.json e stable.json.sig dalla cache/CDN del sito. Devono essere
   raggiungibili direttamente sotto https://www.luigipranzo.com/myfile/Pulse/.

Se il piano non permette script CLI o cartelle private, mantieni gli upload
manuali PULSE-Blog sul sito oppure passa il Mint direttamente a GitHub con
l’upgrade iniziale descritto in docs/PUBBLICAZIONE_GITHUB.txt.

FUNZIONAMENTO
Le nuove release vengono pubblicate con bin/release-github.py. Il relay prende
blog-stable.json, la sua firma e pulse-X.Y.Z.zip dalla stessa release stabile.
Verifica firma Ed25519, tag, versione, compatibilità, scadenza, dimensione e SHA-256.
Pubblica lo ZIP prima del manifest; il Mint effettua una seconda verifica e
crea il backup prima di installare. Se GitHub o il relay falliscono, rimane
l’ultima versione pubblicata. Non vengono cancellati vecchi ZIP o dati del sito.
Il blog pubblica i file del programma, non i dati del negozio. La chiave privata
di firma non serve sul hosting e deve restare sul computer di sviluppo.

Gli allegati richiesti sulla GitHub Release sono cinque:
pulse-X.Y.Z.zip, stable.json, stable.json.sig,
blog-stable.json, blog-stable.json.sig.
Un semplice commit non è un aggiornamento. Durante i due cambi atomici di
manifest e firma un controllo può fallire: il Mint riprova senza installare
file non verificati. Il solo upload di un pacchetto sul blog non attiva il cron.

Guida ufficiale Aruba:
https://guide.aruba.it/hosting-e-domini/hosting/hosting-linux/pannello-controllo-linux/processi-cron
