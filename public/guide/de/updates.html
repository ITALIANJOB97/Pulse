Updates

Der Mint-PC benötigt Internetzugriff auf seine eingerichtete Update-Quelle und muss für das Nachtfenster eingeschaltet bleiben.

Update-Quelle

Die Einstellungen zeigen die Quelle des installierten Dienstes. Bestehende Blog-Installationen verwenden weiterhin luigipranzo.com. Ein Relay auf dem Hosting kann signierte GitHub-Releases im Blog bereitstellen, ohne Token oder Befehle auf Mint. Diese Hosting-Verbindung muss zuerst eingerichtet werden; ein einzelnes Update aktiviert sie nicht. Direkte GitHub-Installationen verwenden einen Token mit Lesezugriff auf Mint. Ein Commit allein ist kein Update: Eine vollständige stabile Release muss veröffentlicht werden.

Verbindung auswählen

Für die bestehende Blog-Verbindung gilt PUBBLICAZIONE_BLOG.txt; das Hosting-Relay ist in docs/RELAY_BLOG.txt beschrieben. Für den direkten Wechsel zu GitHub auf Mint einmal sudo python3 deploy/configure-github-mint.py und anschließend sudo bash deploy/upgrade-mint.sh aus dem entpackten Paket ausführen. Konten, Fotos und Daten bleiben erhalten. Die Ersteinrichtung nicht wiederholen.

Automatische Updates

Alle 30 Minuten wird der signierte Kanal geprüft. Administratoren sehen Version, Änderungen und geplante Installation. Standardzeit: 03:00–04:00, Europe/Zurich. Verpasste Zeitfenster werden verschoben. Eine nicht erreichbare Quelle stoppt die Anzeige nicht.

Steuerung

Jetzt prüfen fordert eine Prüfung an, normalerweise innerhalb von fünf Minuten. In den Einstellungen Stunde ändern oder automatische Installation pausieren. Verschieben verzögert um mindestens 24 Stunden. Erneut versuchen plant nach einem Fehler einen Versuch im nächsten erlaubten Zeitfenster.

Während des Updates

Pulse prüft Paket und Sicherung, pausiert die Bearbeitung kurz und kontrolliert den neuen Stand. Bei Fehlern werden vorherige Version und Datenbank vor Freigabe der Bearbeitung wiederhergestellt. Bei Erfolg lädt der TV neu und zeigt den Installationshinweis. Den PC dabei nicht absichtlich ausschalten.

Bei Problemen

Das Upgrade erstellt einen Textbericht im Ordner diagnostica neben dem Paket. Für Support auf USB kopieren. Alternativ sudo bash deploy/diagnose-mint.sh ausführen. Wenn die Wiederherstellung nicht abschliesst, Dateien belassen und Bericht weitergeben; /var/lib/pulse nicht löschen und Setup nicht wiederholen.
