Updates

The Mint PC needs Internet access to its configured update source and must remain powered on for the night window.

GitHub / Blog

Settings shows the source used by the installed service. GitHub public mode (service v3) needs no token. Existing blog installations keep using luigipranzo.com; a configured hosting relay can fetch public GitHub releases without a token. A complete signed stable Release is required; a commit alone is not an update.

Mint

To keep the existing blog connection, follow PUBBLICAZIONE_BLOG.txt and docs/RELAY_BLOG.txt. To switch Mint directly to public GitHub, run sudo bash deploy/upgrade-mint.sh once from the extracted package. This updates the system service and preserves accounts, images and data. Do not repeat initial setup.

Automatic updates

Pulse checks the configured signed channel every 30 minutes. The administrator sees the version, release notes and planned installation. By default an update starts between 03:00 and 04:00, Europe/Zurich. A missed window is deferred. An unavailable source does not stop the display.

Your controls

Check now queues a request for the service, normally within five minutes. Change the hour or pause automatic installation in Settings. Postpone delays installation for at least 24 hours. Retry after a failed update schedules another attempt in the next permitted window.

During installation

Pulse verifies the package and safety backup, briefly pauses editing, switches the code and checks the result. A failure restores the previous version and database before editing resumes. After success the TV reloads and shows the installed-version notice. Do not power off intentionally while this is happening.

If something fails

The upgrade creates a text report in diagnostica next to the package. Copy it to USB for support. You can also run sudo bash deploy/diagnose-mint.sh. If recovery cannot finish, leave the files in place and send the report; do not delete /var/lib/pulse or rerun setup.
