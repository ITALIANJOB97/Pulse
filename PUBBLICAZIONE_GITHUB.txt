PULSE 0.2.4 — GITHUB PUBBLICO
============================
Repository prevista: https://github.com/ITALIANJOB97/Pulse
La repository deve essere pubblica. La configurazione locale da sola non
cambia la sua visibilità: verificare che sia accessibile anche senza login.
Database, foto, backup, impostazioni locali e chiave privata di firma non
vanno mai caricati su GitHub. La repository pubblica contiene solo codice.

MINT GIÀ CONFIGURATO SUL BLOG
L’aggiornamento automatico della Dashboard mantiene il servizio blog v1.
Puoi continuare senza comandi sul PC usando il relay pubblico su Aruba
(docs/RELAY_BLOG.txt) oppure caricando PULSE-Blog-0.2.4.zip sul blog.
Il relay pubblico non richiede token GitHub.

PASSAGGIO DIRETTO MINT -> GITHUB (UNA SOLA VOLTA)
1. Scarica pulse-0.2.4.zip dalla Release e decomprimilo sul Mint.
   Non usare gli archivi Source code generati da GitHub.
2. Apri un terminale nella cartella estratta ed esegui:
       sudo bash deploy/upgrade-mint.sh
3. Attendi il messaggio di riuscita. Il comando crea e verifica il backup,
   aggiorna il servizio a v3 e conserva dati, utenti, foto e impostazioni.
4. Non ripetere setup o install-mint.sh. Non serve configure-github-mint.py,
   né un token sul Mint: la nuova configurazione pubblica ignora eventuali
   vecchie credenziali rimaste dalla modalità privata.

DOPO IL PASSAGGIO
- Controllo delle GitHub Releases stabili circa ogni 30 minuti.
- Verifica Ed25519, dimensione e SHA-256 prima dell’installazione.
- Avviso con le novità e installazione notturna dopo backup verificato.
- Finestra iniziale 03:00–04:00 Europe/Zurich, modificabile nelle impostazioni.
- Se GitHub è indisponibile o una release è incompleta, la TV continua a funzionare.
- Un semplice commit non è un aggiornamento: occorre una Release firmata completa.

PUBBLICAZIONE DAL COMPUTER DI SVILUPPO
1. Modificare il codice, incrementare VERSION e aggiornare le note EN/DE/FR.
2. Eseguire i test necessari e salvare le modifiche in un commit su main.
3. Eseguire:
       python bin/release-github.py --php PERCORSO_PHP --gh PERCORSO_GH
   PHP 8.3 con le estensioni del progetto e GitHub CLI devono essere disponibili.
   Il comando usa l’accesso di Git Credential Manager o GitHub CLI, esegue i
   test applicativi, prepara gli ZIP, firma con la chiave locale, carica main
   e crea una bozza di Release. Pubblica solo dopo che i cinque allegati sono
   presenti con le dimensioni corrette. Non esegue force push e non sovrascrive
   release esistenti; un errore può lasciare una bozza da controllare.
4. I Mint con servizio v3 scaricano automaticamente. Quelli ancora sul blog
   ricevono la release tramite il relay Aruba, se configurato.

ALLEGATI DELLA RELEASE vX.Y.Z
pulse-X.Y.Z.zip, stable.json, stable.json.sig,
blog-stable.json, blog-stable.json.sig.
Il manifest GitHub richiede updater 3; quello blog resta compatibile con v1.
Per creare solo gli ZIP senza pubblicare:
    python bin/build-linux-mint-zip.py
    php -d extension=sodium bin/publish-release.php publish-blog

La chiave .release-private/signing.key rimane sul computer di sviluppo,
protetta e salvata offline. Non inserirla in Git o in un GitHub Secret.
Le modifiche future al servizio root richiederanno ancora un upgrade esplicito.
